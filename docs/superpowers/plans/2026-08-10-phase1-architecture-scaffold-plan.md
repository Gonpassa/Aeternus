# Aeternus.3 Phase 1 — Architecture Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the empty, working npm-workspaces monorepo skeleton (client + backend + shared-types) described in `docs/superpowers/specs/2026-08-10-phase1-architecture-scaffold-design.md`, with all tooling wired and both apps able to boot.

**Architecture:** Root npm workspaces monorepo (`client/`, `backend/`, `packages/shared-types/`), each package extending a shared `tsconfig.base.json`. Backend is a single Express app with an empty `src/modules/` directory awaiting Phase 4. Client is a Vite + React 18 SPA using TanStack Router (file-based routing) and TanStack Query, styled with Tailwind CSS v4 + shadcn/ui, with an empty `src/modules/` directory and a `src/shell/` layout layer.

**Tech Stack:** TypeScript (strict) end-to-end, Express + Mongoose, React 18 + Vite + TanStack Router/Query, Tailwind CSS v4 (`@tailwindcss/vite`), ESLint (flat config) + Prettier, Jest + Supertest (backend only — client testing tooling is explicitly deferred).

## Global Constraints

- npm workspaces: root `package.json` with `"workspaces": ["client", "backend", "packages/*"]`. One root `npm install` installs everything.
- Root-level shared config: `tsconfig.base.json` (strict compiler options), shared Prettier config, root `.gitignore`. Every package's `tsconfig.json` extends the base.
- Zero shared runtime code between client and backend, except `packages/shared-types` — types only, erased at build, no runtime logic.
- `packages/shared-types` stays an empty re-export barrel in Phase 1 — no speculative types before Phase 4 needs them.
- Backend: feature-folder layout under `src/modules/<module>/` — empty in Phase 1. Cross-cutting concerns at `src/config/`, `src/middleware/`, `src/types/`. Backend lint: `eslint:recommended` + `@typescript-eslint/recommended` + Prettier, with `no-console` as an error.
- Client: `src/shell/` (layout/nav/auth stub), `src/modules/<module>/` (empty in Phase 1), `src/routes/` (TanStack Router file-based, thin files only), `src/routeTree.gen.ts` (auto-generated, never hand-edited), `src/api/` (Axios instance + endpoint map), `src/components/ui/` (shadcn/ui landing spot, empty until a component is needed). Client lint: Airbnb + Airbnb hooks + `typescript-eslint` + `react-refresh` + Prettier.
- Styling: Tailwind CSS v4 via `@tailwindcss/vite` only — no `postcss.config.js`, no `tailwind.config.js`, no Emotion, no MUI. One global `src/styles.css` with `@import "tailwindcss";`.
- No client-side test framework in Phase 1 (deferred — matches spec).
- Git: existing repo on `main`, no remote. Commit after every task.
- No module code (journal, writing, calendar, AI learning), no auth/session logic, no deployment config — all out of scope per spec, start in later phases.

## File Structure

```
Aeternus.3/
├── package.json                    # root workspaces manifest
├── tsconfig.base.json
├── .prettierrc
├── .gitignore
│
├── packages/shared-types/
│   ├── package.json
│   ├── tsconfig.json
│   ├── eslint.config.js
│   └── src/index.ts                # empty barrel
│
├── backend/
│   ├── package.json
│   ├── tsconfig.json
│   ├── eslint.config.js
│   ├── .env.example
│   ├── jest.config.js
│   └── src/
│       ├── app.ts                  # configured Express app (no listen/connect)
│       ├── index.ts                # entrypoint: connectDB() then app.listen()
│       ├── config/{default.ts, database.ts}
│       ├── middleware/auth.ts      # stub
│       ├── types/request.ts        # stub
│       └── modules/                # empty (Phase 4+)
│   └── src/__tests__/app.test.ts
│
└── client/
    ├── package.json
    ├── tsconfig.json
    ├── tsconfig.node.json
    ├── eslint.config.js
    ├── vite.config.ts
    ├── index.html
    └── src/
        ├── main.tsx
        ├── styles.css
        ├── routeTree.gen.ts        # generated by TanStack Router plugin
        ├── routes/{__root.tsx, index.tsx}
        ├── shell/{Layout.tsx, Nav.tsx, AuthProvider.tsx}
        ├── api/{client.ts, endpoints.ts}
        ├── components/ui/          # empty (Phase 4+)
        └── modules/                # empty (Phase 4+)
```

Why `src/app.ts` in addition to the spec's `src/index.ts`: the spec calls `src/index.ts` the entrypoint that "connects to Mongo, wires session/passport middleware, and registers each module's router." To integration-test the Express app shell in Phase 1 without opening a real port or requiring a live Mongo connection, the Express app construction is split into `app.ts` (pure, testable, exported) and `index.ts` (side effects: connect DB, then `app.listen`). This doesn't change the spec's architecture — `index.ts` is still the thin entrypoint — it just makes the app object injectable into tests.
