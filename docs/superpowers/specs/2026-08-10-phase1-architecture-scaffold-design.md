# Nee.3 Phase 1 — Architecture Scaffold Design

## Context

Nee.3 is the planned rewrite of Harmonee as a modular personal hub (journal, structured writing, calendar, AI-assisted learning), documented in `README.md`.
As of this design, Nee.3 contains only that README — no code, no repo.
This spec covers **Phase 1 only**: the project setup and shared architectural shell that every module (starting with the journal in Phase 4) will sit on top of.
It does not design any module's internals — those get their own brainstorm/spec when their phase starts, per the README's "no premature abstraction" principle.

## Goals

- Stand up a working, empty full-stack skeleton (client + backend + shared types) with consistent tooling.
- Establish folder conventions so that adding a module later means adding a folder, not restructuring the app.
- Keep client and backend runtime-independent, per the README's separation-of-concerns principle, while eliminating tooling-config duplication between them.

## Repo & tooling

- Nee.3 becomes its own git repository (`git init`, branch `main`, matching `harmonee/` and `Nee.2/`'s convention). No remote is configured yet.
- **npm workspaces** monorepo: a root `package.json` with `"workspaces": ["client", "backend", "packages/*"]`. One `npm install` at the root installs all three packages' dependencies.
- Root-level shared config: `tsconfig.base.json` (shared strict compiler options), a shared ESLint/Prettier base, root `.gitignore`.
- This is a deliberate departure from Nee.2, which kept `client/` and `backend/` as fully independent packages with no root tooling. The workspaces model removes config duplication (one root TS/lint base instead of two copies to keep in sync) without violating "no shared runtime code" — workspaces link dev tooling and installs, not application logic.

## Shared types package

- New workspace: `packages/shared-types/`. Pure TypeScript, zero runtime dependencies — only type definitions for API request/response shapes, grouped by module (mirroring the module structure used in `client/` and `backend/`).
- Both `client` and `backend` add it as a workspace dependency and import API contract types from it, so a request/response shape is defined once and can't drift out of sync between the two sides.
- This is the one deliberate exception to "no shared runtime code": it ships no runtime logic, only compile-time types erased at build time, so nothing actually executes across the client/backend boundary.
- Empty (just a re-export barrel) until Phase 4 adds the journal module's first types.

## Backend architecture

- Single Express app (`backend/src/index.ts`) serves all modules — not separate services per module.
- Feature-folder layout: `src/modules/<module>/` each owns its own `routes.ts`, `controller.ts`, and Mongoose `model.ts` (e.g. `src/modules/journal/{routes.ts, controller.ts, model.ts}`).
- `src/index.ts` stays thin: connects to Mongo, wires session/passport middleware, and registers each module's router (`app.use('/api/journal', journalRouter)`).
- Cross-cutting concerns that don't belong to a single module live at the top level, matching Nee.2's existing pattern for these pieces: `src/config/` (env, DB connection), `src/middleware/` (auth), `src/types/` (`AuthenticatedRequest`).
- Phase 1 scaffolds the shell only — `src/index.ts`, config/middleware skeletons, and an empty `src/modules/` directory. No module code is written; that starts in Phase 4.

## Client architecture

- **`src/shell/`** — app-wide layout, navigation linking to each module, and the auth context/provider gating the app. Every module renders inside the shell's layout.
- **`src/modules/<module>/`** — each module's components, TanStack Query hooks, and module-specific types, mirroring the backend's structure.
- **`src/routes/`** — dictated by TanStack Router's file-based routing plugin (scans this folder to build `routeTree.gen.ts`, mapping URL paths to files). Route files stay thin: each one imports and renders its module's top-level component (e.g. `src/routes/journal.tsx` renders `JournalPage` from `../modules/journal`). One route file per URL path, including nested/dynamic ones (`journal/$entryId.tsx`).
- **`src/routeTree.gen.ts`** — auto-generated by the router plugin; never hand-edited.
- **`src/api/`** — Axios instance + endpoint map, shared across modules' query hooks.
- **`src/components/ui/`** — shadcn/ui components, copied into the codebase (not installed as a package) and styled with Tailwind utility classes. Shared primitive layer every module's UI builds on.
- No client-side test framework is set up in Phase 1 (Nee.2 had none either). Revisit if a module's complexity warrants it.

## Styling stack

- **Tailwind CSS v4** via the `@tailwindcss/vite` plugin — no manually-authored `postcss.config.js` or `tailwind.config.js`; the plugin handles processing internally. Setup is: install `tailwindcss` + `@tailwindcss/vite`, add the plugin to `vite.config.ts`, and add `@import "tailwindcss";` plus any theme tokens (CSS variables) to one global `src/styles.css`.
- **shadcn/ui** components (Radix-based, unstyled-by-default primitives) are copied into `src/components/ui/` via the standard shadcn workflow and restyled with Tailwind utility classes.
- This replaces the README's original "Emotion for all styles" principle, which has been updated in `README.md` to "Tailwind + shadcn/ui for all styles." Emotion is dropped from the stack entirely.
- No plain CSS files beyond the single Tailwind entry stylesheet; component-level styling stays in JSX via utility classes.

## TypeScript & linting

- Root `tsconfig.base.json` sets shared strict options (`strict: true`, `noUncheckedIndexedAccess`, etc.). `client/tsconfig.json`, `backend/tsconfig.json`, and `packages/shared-types/tsconfig.json` each extend it with their own `moduleResolution`/`jsx`/output settings.
- Linting stays split per package rather than unified, since client (React) and backend (Node) have different rule needs:
  - Backend: `eslint:recommended` + `@typescript-eslint/recommended` + Prettier, `no-console` as an error (matches Nee.2).
  - Client: Airbnb + Airbnb hooks + `typescript-eslint` + `react-refresh` + Prettier (matches Nee.2).
  - `packages/shared-types`: minimal — `@typescript-eslint/recommended` + Prettier only.
- Root scripts (`npm run lint --workspaces`) run all packages' lint configs from one command.

├── packages/

│       ├── tsconfig.json
│       └── src/

│
├── backend/
│   ├── package.json
│   ├── tsconfig.json
│   ├── .env.example

        ├── main.tsx

## Out of scope for this spec

- Any module's internal design (journal, writing, calendar, AI learning) — each gets its own brainstorm/spec in its own phase.
- Auth/session implementation (Phase 3) — Phase 1 only stubs the files that will hold it.
- Deployment (Phase 8).
- Client-side testing tooling — deferred until needed.
